这个文档站是我给自己做的一个作品集。面试或介绍作品时，我希望用一个链接集中展示写过的技术文档、建站过程和工作思考，省去逐个发送文件的麻烦。

## 为什么要搭一个站

技术文档不像设计作品，可以直接放几张图就看出效果。介绍一篇文档时，还需要说明它写给谁、解决什么问题、为什么这样安排结构，以及读者看完后能否继续操作。

之前我试过几种方式，但都不太合适：

| 方式 | 问题 |
| --- | --- |
| Word / PDF | 文件太分散，别人不一定愿意一个个下载打开 |
| 在线文档 | 有时需要权限，展示起来不够稳定 |
| GitHub README | 适合放项目说明，不适合放多篇长文档 |

所以最后决定搭一个文档站。这样一来，别人打开链接就能看到首页、导览页、文档作品和建站手记，阅读路径会更清楚。

## 我主要做了什么

我不是程序员，搭站时主要负责组织内容和安排入口，让读者知道站点里有什么、应该先看哪篇。

整个过程里，我主要做了这些事：

1. 确定站点用途，用它展示技术文档作品。
2. 把内容分成“文档作品”和“建站手记”两部分。
3. 用 Docusaurus 搭建站点，在网站上展示 Markdown 文档。
4. 整理首页和导览页，让读者能按目标选择文章。
5. 加入格式检查和 AI 评分，检查文档中不规范或没有讲清楚的地方。
6. 部署到 GitHub Pages，让读者能通过链接访问。

其中比较复杂的配置和页面代码，我基本是让 AI 帮我处理。我负责决定“要做成什么样”“内容怎么排”“哪些地方要删掉或重写”。

## 站点现在怎么组织

目前站点主要分成四个入口：

| 入口 | 放什么 | 读者能看到什么 |
| --- | --- | --- |
| 首页 | 站点整体介绍和重点卡片 | 快速知道这个站是做什么的 |
| 站点导览 | 所有内容的阅读路径 | 按目标选择先看哪篇文档 |
| 文档作品 | IoT 概念、接入指南、API 文档 | 展示不同类型技术文档的写法 |
| 建站手记 | 建站过程、质量评分、更新流程、工作思考 | 展示我是怎么维护这个站的 |

文件大致是这样放的：

```text
docs/
├── intro.md              # 站点导览
├── iot-overview.md       # IoT 核心概念
├── iot-platform-guide.md # 小米 IoT 平台接入指南
└── api-docs.md           # IoT 平台 API 文档

blog/
├── 2026-07-01-docs-as-code.md       # 建站过程
├── 2026-07-10-doc-score.md          # 文档质量评估助手
├── 2026-07-14-update-workflow.md    # 文档站更新流程
└── 2026-07-14-iot-doc-thoughts.md   # IoT 文档调研思考
```

这个结构不是一开始就完全想好的，是边写边调整出来的。比如一开始我把“文档调研思考”放在文档作品里，后来发现它更像工作复盘，就挪到了建站手记里。

## 首页直接放几个入口

首页用几个入口引导读者选择内容，自我介绍只占很少篇幅。

- 想看文档作品，可以点到作品集。
- 想看建站过程，可以点到建站手记。
- 想快速判断内容，可以看首页下面的卡片。

读者可以先在首页选择阅读方向，再进入对应页面查看详细内容。

## 导览页怎么想的

作品集里的文章多了以后，读者可能不知道从哪篇开始。因此，我单独做了导览页，帮助读者选择内容。

所以我在导览页里放了几类信息：

| 内容 | 作用 |
| --- | --- |
| 快速选择 | 让读者按目标直接进入对应文档 |
| 站点地图 | 用图看清楚内容之间的关系 |
| 推荐阅读路径 | 告诉不同读者应该先看哪几篇 |
| 文档详情表 | 说明每篇文档适合谁、讲什么、需要多久 |

这样读者不用每篇都点开试，可以先判断哪篇最符合自己的需求。

## 文档作品怎么选的

我从写过的文档中，挑选了几种能展示不同写作能力的内容。

| 文档 | 展示重点 |
| --- | --- |
| IoT 核心概念 | 能不能把抽象概念讲清楚 |
| 小米 IoT 平台接入指南 | 能不能把长流程拆成可执行步骤 |
| IoT 平台 API 文档 | 能不能把接口说明写得清楚、可查 |

这些文档展示了我如何解释概念、拆分步骤、说明接口，以及如何安排截图、表格、排障说明和下一步链接。

## 建站手记放什么

建站手记更像过程记录。我会把和这个站有关的思考放在这里，比如：

- 为什么要搭这个站。
- 文档质量评分怎么接进来。
- 平时怎么更新文档。
- 看完竞品文档后有哪些工作思考。

这些内容不完全是正式文档，更像“我做这件事时怎么想、怎么改、怎么复盘”。

搭站的过程中，我逐渐明确了作品集的呈现方式：先说明有哪些内容，再给出阅读顺序，并让每篇文档展示一种具体的写作能力。之后我还会继续调整内容和入口。
